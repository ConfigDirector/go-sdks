# Go SDKs Plan

Umbrella card: https://trello.com/c/vO00qvNu. Each increment below is one Trello card at the top of the SDK Backlog, in this order. This file moved here from `config-director/product-documents/go-sdk-plan.md` with the bootstrap increment.

## 1. Goals

1. A Go server SDK, `github.com/ConfigDirector/go-sdks/configdirector`, with the same behavior as the Python, Java, .NET and JavaScript server SDKs: local evaluation of targeting rules and segments, streaming and polling connection modes, telemetry, events and watches, and a test client for consumers.
2. A Go OpenFeature server provider, `github.com/ConfigDirector/go-sdks/configdirector-openfeature`, built on the SDK and released on its own.
3. Both proven by the targeting-rules contract and the SDK functional tests, then listed everywhere ConfigDirector lists SDKs.

## 2. Guidelines

- Use the JavaScript, Python, .NET and Java server SDKs as references for behavior. Do not transliterate; follow Go semantics, idioms and standard practice.
- Every change is covered by tests proven effective: written first and seen failing for the right reason, or the implementation mutated afterwards until the test fails for the right reason.
- Comments only as doc comments on exported members.
- Small increments, each self contained, handed over for review and committed by the user before the next starts.
- Integration tests exercise the public API against a stubbed SDK server (`httptest`); no internal component is stubbed.

| --- | --- |
| Repository | Public monorepo `ConfigDirector/go-sdks`, checked out at `/Users/alejandro/Projects/ConfigDirector/go-sdks`. Root `go.work` holds both modules; samples are modules outside it, depending on released versions and checked against the tree in CI. |
| Modules | `configdirector/` (package `configdirector`), tags `configdirector/vX.Y.Z`. `configdirector-openfeature/` (package `configdirectoropenfeature`), tags `configdirector-openfeature/vX.Y.Z`. |
| SDK names | `go-server-sdk` and `go-openfeature-server-provider`, registered in the SDK server and core-api capability tables with segment-conditions minimum `0.1.0`. The provider identifies itself through a closed wrapper list in the SDK. |
| Toolchain | `go` directive is the oldest release Go still supports when the first increment lands (1.26 on 2026-10-09, with 1.27 current); CI tests that and current on ubuntu, macos and windows with `-race`. SDK module depends on the standard library only; the provider adds `github.com/open-feature/go-sdk`. Tests use `testing`, `testify` and `httptest`. Lint through `gofmt`, `go vet` and a pinned `golangci-lint`, all behind `make` targets a pre-push hook shares with CI. |
| Construction | `configdirector.NewClient(Options) (*Client, error)` with an options struct (`SDKKey`, `Metadata`, `ConnectionOptions`, `TelemetryOptions`, `Logger *slog.Logger`, `Hooks`). Zero values are defaults; validation happens in the constructor; connecting starts at once. |
| Readiness | `WaitForReady(ctx) error` returns the context error when the wait ends; the client keeps connecting. `Ready()`, `Closed()`, `Close() error`. |
| Context type | `UserContext{ID, Name, Traits, Anonymous}` (recorded in `config-director/GLOSSARY.md` under Context). |
| Reads | One method per kind: `BoolValue`, `StringValue`, `IntValue` (`int64`), `FloatValue` (`float64`), `JSONValue(key, target, userContext) error`; `*ValueDetails` twins returning `EvaluationDetails{Reason, ValueID, UsedDefault}`; `AllConfigs(userContext, keys...)`. One `Evaluation` type backs details, the evaluated event and telemetry. |
| Events | `Options.Hooks` for construction-time handlers; `OnReady`, `OnConfigsUpdated`, `OnConfigEvaluated` and per-kind `Watch*` return an unsubscribe func. Handlers run on the transport goroutine; panics are recovered and logged. |
| HTTP | `ConnectionOptions.HTTPClient *http.Client`; the functional-test probe counts polls through it. |
| Telemetry `requestedType` | Go type names: `bool`, `string`, `int64`, `float64`, and the reflected target type for JSON. |
| Logging | `*slog.Logger`, default `slog.Default()`, records tagged `component=configdirector`; no level option. |
| Testing package | `configdirector/configdirectortest` in the SDK module, shipped before `v1.0.0`. |
| Versions | `v0.x` until the functional tests pass in dev and the provider is built on it, then `v1.0.0`. `configdirector.Version` is the single source, sent in `User-Agent` and telemetry. |
| Release | Manual `workflow_dispatch` per module: resolve `Version`, refuse an existing tag, require the CHANGELOG section, run the suite, push the tag, create a GitHub Release, request the module from proxy.golang.org. |
| Samples | Gin for the SDK (port 3600) and for the provider (3610), same five keys and context mapping as the siblings, each with a test on `configdirectortest`. A standard-library sample is a follow-up card. |
| Hardening | Strict `golangci-lint` preset with `revive`; `govulncheck`, `gosec`, fuzz targets for the SSE parser, value parser, JSON pointer lookup and payload decoder, all in CI. |

## 5. Progress log

Tick an item above and add one line here per completed increment: date, increment, deviation if any.

- 2026-10-09, increment 0. `go 1.26`, not the 1.25 the card named: Go 1.27 shipped on 2026-08-19 and `github.com/open-feature/go-sdk` v1.19.0 already requires 1.26. The provider's `go.mod` requires testify only for now: `go mod tidy` ignores `go.work` and drops a requirement nothing imports, and the SDK requirement cannot resolve until `configdirector/v0.1.0` is tagged (increment 11); increment 15 adds both.
- 2026-10-09, increment 1. `internal/evaluation` passes all 4,486 condition, 118 bucketing and 60 segment cases. The harness maps the wire shape onto the evaluator's types itself until increment 7 adds the payload parser; an empty context identifier is treated as no identifier (assigned 0.0), where Python and JavaScript hash the empty string.
- 2026-10-09, increment 2a. `WaitForReady` applies `ConnectionOptions.Timeout` as an upper bound on the caller's context and returns `ErrClientClosed` after `Close`; `JSONValue` decodes as `encoding/json` does, after a trial decode so a document that does not fit leaves the target untouched; the `Evaluation` type stays unexported until the events card returns it; a zero `Timeout` is the 3s default and only a negative one is rejected; the `connection` interface reports readiness by delivering its first payload rather than through a separate call. The stand-in connection delivers its payload after 200ms so readiness can be observed through the public API.
- 2026-10-09, increment 2b. `OnReady` registered once the client is ready calls the handler at once, as the card asked; the Java `onClientReady` the card cites never calls a late handler, so this is a deliberate difference. A watch that fires reaches the `OnConfigEvaluated` handlers, as the Python and Java watchers do. `WatchJSON` takes a `newTarget func() any` called for a fresh pointer on every notification and hands that pointer to the handler. A nil handler panics at registration, as `http.HandleFunc` does. The stand-in connection delivers one fixed payload, so the delta, drop and segment scenarios run through a test-only connection in `export_test.go` that delivers payloads on the test's goroutine; increment 7 replaces it with `httptest`.
- 2026-10-09, increment 4. `samples/configdirector/gin` reaches the SDK through a `replace` directive until increment 11 tags it; `make samples-local` lints and tests every sample through a throwaway workspace under `.tools/`, and the `samples` CI job runs it. Against the stand-in connection the five keys evaluate to their in-code default values, so the test asserts those and proves the context through an `OnConfigEvaluated` hook; increment 7b switches it to `configdirectortest` and served values. `.env` is loaded through `github.com/joho/godotenv`, as the Flask sample loads it through python-dotenv. Observation for the API review: `JSONValue` returns an error only for a target that is not a non-nil pointer, so every caller carries an error branch it cannot reach.
- 2026-10-09, increment 5. `internal/eventsource` is pull-based: `Reader.Next()` returns one event at a time, where Python and Java push through callbacks. A goroutine reads the source into 16 KiB chunks so `Next` can time the silence between them; a chunk that arrived while the caller was busy wins over an elapsed stall timer. The reader is seeded with the previous connection's last event id (`Options.LastEventID`), so the transport can carry it across reconnects without Python's None-versus-empty distinction. The 1 MiB line cap also applies to a line that arrives whole in one chunk, which the siblings never check, so parsing does not depend on chunking; `FuzzParse` asserts that by parsing every input whole and byte by byte. A byte order mark is stripped from the first line rather than the first chunk, so one split across chunks still goes. Bytes pass through undecoded; Python replaces invalid UTF-8.
- 2026-10-09, increment 6a. `internal/transport` holds the streaming transport and the pieces polling will share (options, meta context, URL joining, session ids, the fatal-status rule, `Retry-After` parsing, the 32 MiB body cap). `transport.OpenStreaming(options, deliver)` delivers each event's data as a string; the wiring card adapts it to the client's `connection` interface and parses payloads. A delay the server names, the stream's `retry` field or a 429's `Retry-After`, is used as it is, without jitter, and the `retry` field applies to the next reconnect only rather than for the life of the transport as the WHATWG algorithm has it, so an outage behind a proxy still backs off; Java and Python ignore the field. The `Retry-After` of a 503 is not read: the card names 429 only, which is what the SDK server sends on suspension. Any 2xx opens the stream, where Java stops on a 204. An unusable URL, including a scheme other than http or https, fails at the first attempt without a request. The connect timeout, 30 seconds, is a timer that cancels the request, since a context deadline would also end the stream; it covers the wait for the response headers and, on a refusal, the read of its body, and stops once a stream opens. `eventsource.Reader` gained `Done()` so the transport can wait for the reading goroutine before it reconnects or returns from `Close`.
- 2026-10-09, increment 6b. `transport.OpenPolling(options, interval, deliver)` sits beside `OpenStreaming` and shares its options, session ids, URL joining, fatal-status rule, `Retry-After` parsing and body cap; one session id lasts the transport's life. The transport finds the payload's `timestamp` with a minimal decode of the body and echoes it as `lastUpdateTimestamp`, so a body that is not JSON, or longer than 32 MiB, is logged at error level and not retried; the full parse stays with increment 7. The SDK server's server-SDK payloads carry no `timestamp` today, so every poll is answered with a full config set, as it is for Java and Python. A network failure is a request error while the request's 30 second deadline has not passed, which covers the body read too; the deadline is a context timeout on the whole exchange, where streaming uses a timer so the stream can outlive it. A 429 waits the longer of its `Retry-After` and the interval, since both are lower bounds on the next poll; Java and Python ignore the header. Any 2xx other than 204 is a payload, as any 2xx opens a stream. The close mechanics both transports share, a cancelled context, a done channel and the close timeout, moved into a `shutdown` type each transport embeds, and the close-timeout error no longer names the streaming transport.
- 2026-10-09, increment 7. `NewClient` opens `transport.OpenStreaming` or `OpenPolling` from the validated mode and parses every delivered document in `server_payload.go`; the stand-in connection and the `export_test.go` seam are gone, and every client test runs against an `httptest` SDK server that serves wire-shaped payloads. The parser follows Python's `_bundle.py`: a config fails as a whole when it has no id, key, type or target, when a rule has no id, when an attribute condition lacks its attribute, operator or target type, when a segment condition lacks its operator or segment id, or when a condition's kind is unknown; a segment fails when it has no groups or a group holds a condition that is not an attribute condition. A message that is not a JSON object with a `configs` object is logged at error level and dropped, where Python logs a missing `configs` at debug. `payloadVersion` is compared as a number, so a missing field is not a mismatch. A `kind` other than `delta`, a missing one included, is read as a full payload, as Python reads it. A full payload keeps the previously held definition of every config it could not read, which also keeps the key out of `RemovedKeys`. `WaitForReady` keeps applying the connection timeout to every call, so a test that proves the client keeps connecting observes `OnReady` instead of waiting twice. Three Python divergences, none reachable with today's server: a `targetValues` entry that is not a string fails the config where Python stringifies it; a non-string `value` or `defaultValue` becomes its compact JSON text, as the Rust `permissive_string` writes it, where Python renders `26.0` as `26`; `variations` and `typeConstraints` are not read, since nothing in the client uses them. The Gin sample test runs its client in polling mode against a local server that serves no configs until 7b replaces it with `configdirectortest`. Run by hand on 2026-10-09 against `server-sdk-api.configdirector-dev.com` with the functional tests' server SDK key, in streaming and in polling mode: ready within the first second, 18 configs received with no warning, and `/configs` answered with the in-code default values because that project does not hold the sample's five keys.
- 2026-10-09, increment 7b. `configdirector/configdirectortest` builds its client through `internal/connectionseam`: package `configdirector` registers `newClientOverConnection` there when it initializes, and `configdirectortest` asserts the func's type once at its own initialization, so the SDK's public API gains nothing and only this module can wire a connection in; the internal in-memory connection delivers wire-shaped JSON documents, so the production payload parser is in the loop. `HoldInitialization()` is a construction option rather than a method: a Go client connects as soon as it is created and the code under test has no `initialize()` call for a held connection to intercept, so `NewTestClient` delivers the stored values on the calling goroutine before it returns, and the client is ready when it does, unless held. `FailInitialization()` cannot end a blocked `WaitForReady` early, since production's refused SDK key waits the timeout out too; it logs the failure at error level and leaves the client not ready, and `CompleteInitialization()` still delivers afterwards. `SetValue` and `ReplaceValues` return an error for a value that cannot be served, as the card preferred, and `NewTestClient` panics for one, as its card signature has no error. `WithHooks` is an option because `Options.Hooks` is the only way to see the first update; a struct is accepted as a JSON config beside maps, slices and arrays, JSON text is given as a `json.RawMessage`, and every integer kind, `time.Duration` included, is an integer config. Updates go through a queue so one made from inside a handler is delivered after the one being handled, as the single transport goroutine would. Telemetry (increment 8) must be created inside `newClient` from the seam's settings so the test client can discard it. The SDK module had no README, so `configdirector/README.md` now holds the "Test your code" section the card asked for, with a short install and first-read above it.
- 2026-10-09, increment 8. `internal/telemetry` holds the collector, the event ring and context registry, the HTTP reporter and the value ids; `internal/transport` exports `EndpointURL`, `JSONRequest`, `IsFatalStatus` and `DiscardResponseBody` for the reporter, and `internal/evaluation` exports `NumberText`. The collector is passed into `newClient`, so `newClientOverConnection` hands the test client a `Discarding` one. Values are rendered on the reading goroutine, scalars as the text the SDK reads them from and documents through `encoding/json` without HTML escaping, and digested on the reporting goroutine. A typed read of a JSON config reports both values as documents, as Python's `_is_json` does; a `JSONValue` read reports both as documents whatever the config's type, where Python renders a non-JSON config's default with `str()`. `evaluatedValueId` carries only the id the SDK server sent, since `Evaluation.ValueID` is empty on a default read (increment 2a), where Python computes one for every evaluation; the SDK server reads neither it nor `type`. The requested type of a `JSONValue` target is the type's name when it has one (`limits`) and its Go spelling otherwise (`map[string]interface {}`). `Close` waits for the final report for at most 5 seconds; when a report already in flight holds it up, it returns with a warning and the reporting goroutine ends with that report in the background, as Java's `close(timeout)` abandons it. A captured context's traits map is cloned when it is captured, so an application that reuses the map after a read does not race the reporting goroutine. Rendering a value for telemetry happens on the reading goroutine as in Python, and still does after a fatal status has stopped collection; only the digest waits for the report. The first-flush, fatal-status and server-error scenarios wait out the real 5 second initial delay, so three tests take about 5 seconds each and run in parallel.
- 2026-10-09, increment 9. `.golangci.yml` moves from the standard preset to standard plus `revive` (the default rules and a curated set on top: import shadowing, unchecked type assertions, unused receivers, data races, `any`, `errors.New`), `gocritic`, `errorlint`, `exhaustive` with a default arm counting as exhaustive, `nilerr`, `bodyclose`, `contextcheck`, `noctx`, `modernize` and `testifylint` without its float and encoded comparison checks, which the exact-text assertions in the transport and test client specs would trip; `gosec` stays with increment 10. No exported name or behavior of the SDK changed, so the CHANGELOG has no line: the review against Effective Go and the API review checklist found no stutter, every option validated once in `settingsFrom`, `ErrClientClosed` the one sentinel a consumer branches on, `WaitForReady` the one method that takes a context, no `time.Sleep` on a production path, and `sync.Once` on every one-shot transition. Internals: `evaluation.EvaluationContext` is `evaluation.Context`, the `internal/evaluation` exports carry doc comments, `transport.Options.PostJSON` sends a JSON request and keeps only the status for the heartbeat and the telemetry reporter, so `JSONRequest` and `DiscardResponseBody` are unexported again (`bodyclose` could not see a body closed by a helper in another package), the streaming reconnect is a `case` of its own, and the Gin sample's shutdown context derives from the serving context through `context.WithoutCancel`; the sample is linted by `make samples-local`, so its findings had to go too. The reporter's two warnings for a request that could not be built and one that could not be sent are one warning now, since `PostJSON` answers both with an error. Test edits go beyond the renames: `new(expr)` replaces the `pointerTo` and `order` helpers, `require.Empty` replaces equality with an empty string, `strings.SplitSeq` replaces `Split`, unused receivers are blank, and the Gin test's request helper takes the test for `t.Context()`.
- 2026-10-09, increment 10. `make check-all` gained `vulncheck`, a pinned `govulncheck` under `.tools/` run from each module's directory since it reads one module at a time, and `fuzz`, every target in `FUZZ_TARGETS` for 20 seconds; `.golangci.yml` enables `gosec`, and CI runs vulncheck and fuzz in a `hardening` job. govulncheck scans the standard library of the Go that runs it, so it fails on a Go behind its latest patch release: the local 1.26.5 has 13 findings fixed in 1.26.9, and the pass was verified with `GOTOOLCHAIN=go1.26.9`. Findings: a refusal's body was logged whole, up to 32 MiB, and with the SDK key should the server echo it; it is logged up to 1 KiB with the key redacted, through `Options.redactedRefusalError`. gosec flagged `math/rand` for the backoff jitter, which `randomFraction` draws from `crypto/rand` now. The review found no data race, leak or re-entrancy problem: `receive` emits outside the lock, so a handler may read, watch or register, and `Close` waits for the transport, heartbeat, reader and telemetry goroutines, which three non-parallel tests count by stack frame. `Close` called from inside a handler waits out the 5 second close timeout and returns its error, since the handler runs on the goroutine `Close` waits for; left as the documented timeout. New fuzz targets: `FuzzParseValue` (bool, int, float and JSON against the standard library, with a half-fitting document to prove the target stays untouched), `FuzzParseServerPayload` (accounting of every config and segment as read or unreadable, seeded from the contract's 34 distinct segment cases) and `FuzzTraitAtPointer` (a member is selected by exactly one pointer, seeded with the contract's 93 trait pointers); the budgets found only oracle gaps, a `kind` that is not text and a boolean spelled with the long s that `strings.EqualFold` folds to an s where the SDK lower-cases, both kept as named corpus entries. `BenchmarkBoolValue` is the smoke benchmark behind `make benchmark`, a measurement outside `check-all`; the SDK server harness and client helpers take `testing.TB` so it shares them.
